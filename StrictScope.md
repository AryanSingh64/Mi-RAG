STRICT SCOPE RULE:

When I ask you to improve the frontend wording, UI copy, README, project description, or documentation:

DO NOT:

* refactor code
* change architecture
* change APIs
* change database logic
* add dependencies
* introduce new features
* remove features
* rename code identifiers
* change functionality
* rewrite working code unnecessarily

Only change what is necessary for the requested frontend content and documentation improvements.

If you believe a code change is necessary, STOP and explain why before making it.

Treat "improve" as "make clearer and better presented", NOT "add more features" or "make the technology sound more advanced."
